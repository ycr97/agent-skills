# 使用示例

以下示例用于说明该 Skill 应当触发、不应触发的场景，以及预期的交互方式。

## 应触发：深入学习技术概念

用户：

> 学习：为什么 TCP 是字节流协议，却仍然可以实现可靠传输？

预期行为：

1. 提炼“可靠、有序的字节交付”背后的核心原理。
2. 从丢包、乱序、序列号空间、确认、重传和接收缓冲区等基本事实逐步推导。
3. 区分字节流抽象与报文级传输机制。
4. 检验“调用一次 `send` 就对应一次 `receive`”之类的常见误解。
5. 在结束教学前，先给出一道预测或应用问题让用户作答。

## 应触发：理解真实机制

用户：

> 我会用 MySQL 索引，但一直没有真正理解为什么 B+Tree 比红黑树更适合作为磁盘索引，教我吃透。

预期行为：

从存储层级和 I/O 成本出发，而不是背诵数据结构定义；逐步讲清扇出、树高、页局部性、范围扫描以及不同工作负载带来的影响。

## 应触发：掌握一项技能

用户：

> 教我从网络基础一路理解到能自己写一个 TCP tunnel，不要只给教程步骤。

预期行为：

将其视为分阶段学习路径：先诊断前置知识，再讲解网络核心原理，并通过逐步接近真实场景的实现练习建立独立解决问题的能力。

## 不应触发：简单事实查询

用户：

> TCP 默认端口是多少？

预期行为：

直接回答事实问题。除非用户明确要求学习相关概念，否则不要启动完整教学协议。

## 不应过度教学

用户：

> B+Tree 和 B-Tree 最大区别，一句话。

预期行为：

遵守用户对简洁程度的要求，不要强制展开成长篇课程。
